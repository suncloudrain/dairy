# 产品需求：v0.1

更新日期：2026-10-09  
状态：已确认的产品基线；基础工程、数据层及日记新建／内容编辑／自动保存已实现，完整 v0.1 尚未完成。已保存日记的显式日期修改及其他后续功能仍按阶段推进。当前交付与验证状态见 [README.md](../README.md)。

本文回答“软件要做什么、用户操作后应该发生什么”。技术组成见 [ARCHITECTURE.md](ARCHITECTURE.md)，选择理由和历史见 [DECISIONS.md](DECISIONS.md)。后续修改需求时，应同步检查这两份文档。

## 1. 产品目标

这是一个供个人使用的日记与任务管理应用，使用 Flutter，支持 Android 和 Windows。

v0.1 的目标是：用户可以在断网时记录日记、管理任务，并在关闭后重新打开应用时读取已经成功保存的数据。

- 本地优先，SQLite 是本版本的持久化数据来源。
- 两个平台分别保存各自的本地数据；v0.1 不会自动互通。
- 未来加入多设备同步，因此记录使用稳定 UUID，并保留创建时间、修改时间和删除标记。
- 第一版优先完成可靠的记录、编辑和恢复流程，保持页面和操作简单。

## 2. v0.1 功能范围

| 模块 | 包含的功能 |
| --- | --- |
| 日记 | 每天一篇、纯文本、可选标题、补写、修改日期、自动保存、查看列表、软删除 |
| 日记回收站 | 查看已删除日记、只读详情、恢复、日期冲突提示、手动复制正文 |
| 任务 | 新建、编辑、手动保存、完成、撤销完成、软删除、范围和完成状态筛选 |
| 任务范围 | 自然日 DAY、自然月 MONTH、自然年 YEAR、自定义连续日期范围 CUSTOM |
| 平台与存储 | Android、Windows、SQLite 本地持久化、基础响应式布局、数据库版本升级机制 |

## 3. 日记

### 3.1 内容和日期

每篇日记包含 UUID、可选标题、正文、日记日期、创建时间、最后修改时间，以及内部使用的删除时间。

- 每个日历日期最多有一篇未删除日记，可以反复编辑。
- 正文为纯文本，保留换行；标题可以为空。
- 无标题时，列表使用日期及正文摘要帮助识别，展示用的替代标题不写回数据。
- 日记日期表示“记录的是哪一天”，与实际创建时刻分开保存。
- 普通标题和正文编辑保留原创建时间与日记日期，只在内容实际变化后更新修改时间；日期只能通过明确的日期修改操作改变。
- 支持补写和修改日记日期。
- 修改到已有未删除日记的日期时，弹窗提醒，不覆盖、不合并。已有日记的原日期不变，当前输入内容保留。
- 新建过程中遇到日期冲突也不能创建第二篇未删除日记或丢弃当前输入，应提示用户处理日期。
- “写今天的日记”先查找今天的未删除日记：存在则打开，不存在则进入尚未创建记录的编辑页。

### 3.2 创建与清空

- 仅打开编辑页不创建数据库记录。
- 开始输入标题或正文后，进入自动保存流程。
- 新建记录的 UUID 在首次创建过程中生成，此后重复保存使用同一个 UUID。
- 已保存日记的标题、正文被清空后，日记仍存在，不自动删除。
- 清空后的日记仍占用其日期；需要通过删除操作将其移入回收站。

### 3.3 自动保存

自动保存是日记编辑的正常保存方式，不要求用户点击保存按钮。

| 场景 | 行为 |
| --- | --- |
| 输入后短暂停顿 | 自动保存最新内容 |
| 持续输入 | 周期性保存，不能无限等待输入停顿 |
| 正常返回、切换日记或主入口 | 提交并等待最新保存；失败时保留编辑内容，提示重试，不能静默丢弃 |
| 进入后台或窗口关闭通知到达 | 尽力提交，不能只依赖退出通知保存 |
| 保存成功 | 只有当前最新内容已经成功写入，才显示“已保存” |
| 保存失败 | 明确显示失败并允许重试，保留当前编辑内容 |

初始调度建议为停顿约 800 毫秒保存、持续输入时约每 5 秒提交一次快照。这些是可调整的实现参数，不是实时性能承诺；已有保存正在执行时不能无限积压请求。

保存状态至少能够区分未保存、保存中、已保存、保存失败。旧内容的保存结果不得覆盖新内容，也不得把仍有修改的页面标记为全部已保存。

突然断电、强制结束进程等情况下，尚未写入数据库的最后一段输入可能丢失。验收保证针对已成功提交的数据，不承诺任何情况下都不丢失尚未保存的输入。

### 3.4 删除

- 删除采用软删除：记录删除时间，保留原 UUID、日期、标题和正文。
- 普通日记列表只显示未删除日记。
- 删除前应处理当前输入及待执行的自动保存；不能因为延迟保存而让日记重新出现。
- 已保存日记从编辑页删除时，先保存当前内容，再完成软删除；如果失败，保留编辑内容并提示。
- 同一日期的已删除日记不占用“一天一篇”的名额，可以重新为这一天写日记。

## 4. 日记回收站

### 4.1 页面和查看

- 回收站从日记列表进入，仅包含日记。
- 按删除时间倒序展示，同时显示原日记日期、标题或正文摘要。
- 点击记录进入只读详情，允许查看、选择和复制正文，不在回收站直接编辑内容或日期。
- v0.1 不提供任务回收站。

### 4.2 恢复

| 情况 | 行为 |
| --- | --- |
| 原日期没有未删除日记 | 恢复原记录，重新出现在日记列表 |
| 原日期已有未删除日记 | 弹窗提示冲突，恢复失败，原有日记和被删除日记均保持原状 |
| 数据库操作失败 | 显示失败，保留回收站记录，允许重试 |

恢复成功后保留原 UUID、创建时间、日记日期和内容，清空删除时间，更新最后修改时间。

冲突时，用户可以进入已删除日记的只读详情，点击“复制正文”，再通过“打开现有日记”进入同日期的正常日记，自行粘贴和整理。

- 仅在用户明确点击复制时写入剪贴板，成功后提示“正文已复制”。
- 不在恢复失败时自动覆盖剪贴板。
- 复制或打开现有日记不会恢复、删除或合并任何记录。
- 不自动追加正文，不覆盖已有日记，不自动替用户选择新日期。

v0.1 不提供永久删除、批量恢复、定时清空和自动合并。软删除记录保留在本地数据库中。

## 5. 任务

### 5.1 内容和保存

每个任务包含 UUID、必填标题、可选备注、任务类型、目标日期范围、完成状态、完成时间、创建时间、修改时间，以及内部使用的删除时间。

- 标题不能仅由空白字符组成；备注为纯文本，可以为空。
- 新建或编辑任务后点击“保存”，成功后返回列表。
- 尚未保存的任务表单不直接改变数据库记录。
- 有未保存修改时返回或取消，应提示用户处理，不能静默丢弃。
- 完成、撤销完成和删除是独立操作，操作成功后立即持久化并刷新页面。

### 5.2 四种目标范围

| 类型 | 用户输入 | 含义 |
| --- | --- | --- |
| DAY | 一个日期 | 该自然日内的一个任务 |
| MONTH | 一个年月 | 该自然月内的一个任务 |
| YEAR | 一个年份 | 该自然年内的一个任务 |
| CUSTOM | 开始日期和持续天数 | 连续若干日内的一个任务 |

- DAY、MONTH、YEAR 的起止日期由程序根据选择自动计算。
- CUSTOM 的持续天数为正整数，可提供 5、10、30 天快捷选项，也可自行输入。
- 开始日期计入持续天数，界面明确展示实际起止日期及共计天数。
- 例如从 2026-10-07 开始持续 5 天，显示“2026-10-07 至 2026-10-11，共 5 天”。
- 日期范围只精确到日，不设置几点几分的截止时间。
- 自然月不等于固定 30 天；CUSTOM 可以跨月、跨年。
- 四种类型的任务都只需完成一次。CUSTOM 不表示每天打卡，不会自动生成多个任务。
- 不实现周期重复、父子任务、日月年自动拆分或完成状态汇总。
- 过期但未完成的任务仍保留原日期范围，不自动顺延，也不自动标记完成；之后仍可手动完成。

### 5.3 完成与删除

| 操作 | 完成状态 | 完成时间 | 删除时间 |
| --- | --- | --- | --- |
| 标记完成 | 改为已完成 | 写入本次完成时刻 | 不变 |
| 撤销完成 | 改为未完成 | 清空 | 不变 |
| 软删除 | 保留原值 | 保留原值 | 写入删除时刻 |

- 上述实际状态改变均更新修改时间。
- 对已经完成的任务重复执行完成，不重写原完成时间。
- 撤销完成后再次完成，记录新一次完成的时刻。
- 删除不等于撤销完成。软删除任务不再出现在正常列表，v0.1 没有用户恢复任务的入口。

### 5.4 列表和筛选

- 提供 DAY、MONTH、YEAR、CUSTOM 四个入口或类型切换项。
- DAY、MONTH、YEAR 分别按所选日、月、年查看，进入对应类型时默认当前周期。
- CUSTOM 单独列出自定义范围任务，显示完整起止日期；v0.1 不自动混入每日、每月或每年列表。
- 提供全部、未完成、已完成筛选。
- 全部视图中未完成任务在前、已完成任务在后，同组使用稳定顺序，避免页面刷新时无规律跳动。
- 不同类型的列表彼此独立，例如 MONTH 任务不会自动显示在 DAY 列表中。

## 6. 页面和跳转

主入口为“日记”和“任务”。不额外增加首页仪表盘。

| 页面 | 入口 | 主要操作和去向 |
| --- | --- | --- |
| 日记列表 | 主导航：日记 | 按日记日期倒序查看；打开、新建日记；进入回收站 |
| 日记编辑页 | 列表记录、新建、写今天、冲突后打开现有日记 | 编辑并自动保存、修改日期、软删除、返回列表 |
| 日记回收站 | 日记列表 | 查看删除记录、进入只读详情、返回列表 |
| 已删除日记详情 | 回收站记录 | 复制正文、恢复；冲突时可打开同日期现有日记 |
| 任务列表 | 主导航：任务 | 切换类型、选择周期、筛选完成状态、完成或撤销完成、新建和编辑 |
| 任务编辑页 | 任务列表 | 编辑表单、保存、取消、软删除已有任务 |

Android 与 Windows 使用同一套业务规则，布局按可用窗口宽度调整。窄屏使用底部导航、独立列表和编辑页；宽屏可以使用侧边导航并限制正文宽度。v0.1 不要求同时显示左右分栏编辑器。

## 7. 明确不包含的功能

- 账号、服务器、云同步、多设备冲突合并。
- 日记图片、附件、富文本和 Markdown 编辑或预览。
- 重复任务、每日打卡、提醒通知、子任务、任务间依赖及自动汇总。
- 日记自动合并、永久删除、回收站定时清空、批量恢复、任务回收站。
- 自定义范围任务自动展开到每一天，或跨类型汇总的“今日看板”。
- 搜索、标签、统计仪表盘、导入导出和备份恢复界面。

这些功能不因“未来可能需要”而提前实现，需要单独确认范围。未来同步、丰富的日记内容和重复任务是已提及的演进方向，不代表已承诺具体版本。

## 8. 分阶段交付与验收

阶段依次推进，每个阶段都应有独立、可演示的验收结果。

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| 0：需求与架构 | 本文及架构、决策文档 | 日记、回收站、四类任务和版本边界无相互矛盾 |
| 1：应用骨架 | Flutter 工程、主导航、基础适配 | Android 和 Windows 均能启动，导航及窗口缩放可用 |
| 2：本地数据 | 模型、SQLite、仓库、升级入口 | 增删改查、日期唯一性、软删除和重新打开数据库的测试通过 |
| 3：日记闭环 | 列表、新建、编辑、补写、修改日期 | 内容能保存并重新打开；重复日期不覆盖；清空不删除。可暂用显式保存验证存储 |
| 4：自动保存 | 调度、状态提示、重试、离页处理 | 连续输入和快速切换不写错内容，保存失败不显示成功，替换阶段 3 的临时显式保存 |
| 5：日记回收站 | 删除、查看、复制、恢复和冲突处理 | 无冲突能恢复；有冲突保留两篇记录；删除不被延迟保存撤销 |
| 6：基础任务 | DAY、MONTH、YEAR 和状态操作 | 自然周期边界正确，手动保存和完成时间规则正确，过期不顺延 |
| 7：自定义范围 | CUSTOM 编辑与独立列表 | 5、10、30 天及自填天数正确，跨月跨年正确，只完成一次，不混入其他类型列表 |
| 8：可靠性与发行 | 升级检查、异常处理、双平台发行包 | 升级保留记录与 UUID；断网完整流程、重启持久化、中文输入和发行包均通过验证 |

实现阶段运行相关格式化、静态分析和测试。关键流程须在 Android 与 Windows 分别验证，不能以一个平台通过代替另一个平台通过。

每个有意义的功能交付时，说明修改文件及其职责、数据流、自动化验证结果和手动验收方法，帮助项目所有者理解完整应用如何工作。

- 产品行为以本文为准；新增功能先明确是否属于当前版本。
- 行为变化同步更新验收标准；涉及数据流或表结构时更新架构文档。
- 重大取舍记录到 DECISIONS.md，保留旧决策被替代的原因。
- 本文描述目标行为，不表示这些功能已经实现；实现进度应以代码和验收结果为准。
