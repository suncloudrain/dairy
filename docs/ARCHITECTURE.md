## 1. 总体结构

采用轻量分层，按功能组织页面。不引入完整的复杂架构框架，也不为每个操作预先增加额外层。

```text
页面：日记、回收站、任务
        ↓ 用户操作       ↑ 状态与结果
页面状态：编辑内容、加载、筛选、保存调度
        ↓ 业务操作       ↑ 数据对象与错误
数据仓库：日记规则、任务规则、统一的数据访问入口
        ↓ 存储请求       ↑ 查询和提交结果
SQLite 数据层：数据库连接、查询、事务、约束、版本升级
```

依赖从上向下。数据层不引用页面；页面不执行 SQL；仓库不访问输入框或导航组件。日期范围计算和数据对象使用普通 Dart 表达，不依赖 Widget。

| 职责 | 内容 | 边界 |
| --- | --- | --- |
| 页面层 UI | 显示内容、接收输入、弹窗、导航、调用剪贴板 | 不决定数据库表结构，不直接写 SQL |
| 页面状态层 | 当前输入、筛选、加载状态、自动保存定时器、保存序列、失败重试 | 不决定数据库文件路径，不把导航当作数据持久化 |
| 数据仓库层 Repository | 日记与任务读写入口、规则校验、UUID 和时间赋值、软删除和恢复 | 不依赖 Flutter 页面；把日期冲突等结果返回调用方 |
| SQLite 数据层 | 打开数据库、参数化查询、事务、索引和约束、升级 | 不决定按钮文案或页面布局 |

“仓库”是操作数据的统一入口，不是另一份数据库。“事务”使相关修改一起成功或一起失败。例如完成状态和完成时间不能只保存一个。

## 4. 数据模型

### 4.1 存储约定

- SQLite 字段采用 snake_case；Dart 属性采用相应的 camelCase。
- UUID 存为 TEXT 主键并显式要求非空；创建后保持不变。
- 日历日期存为固定宽度的 `YYYY-MM-DD` 文本，必须是有效日期。
- 创建、修改、完成、删除时刻存为 UTC Unix 毫秒整数，显示时转换到本地时区。
- 可空字段使用 NULL 表示没有值；布尔状态存为整数 0 或 1。
- 日记正文允许空字符串，以支持编辑和清空后保留记录。
- 只有实际数据变化才更新 updated_at，浏览或重复保存相同内容不更新时间。
- 时间来自本机时钟，不假设跨设备时间严格有序，不把 updated_at 当作同步版本号。
- 读取时构造数据对象，写入前完成业务校验；SQL 参数使用参数绑定。

日期与时刻的含义不同：2026-10-05 的日记可以在 2026-10-07 创建。日记日期和任务范围不因切换时区而转换到前一天或后一天；“今天”根据设备当前本地日历计算。

### 4.2 公共字段

下列字段同时存在于日记和任务表，不需要额外的公共实体表。

| 字段 | SQLite 类型 | 规则 |
| --- | --- | --- |
| id | TEXT | 主键、不可空、UUID v4 |
| created_at | INTEGER | 不可空，首次创建时写入，后续保留 |
| updated_at | INTEGER | 不可空，实际修改、删除或恢复时更新 |
| deleted_at | INTEGER | 可空；NULL 为正常记录，非空为软删除记录 |

### 4.3 日记表 diary_entries

包含公共字段，并增加：

| 字段 | SQLite 类型 | 规则 |
| --- | --- | --- |
| title | TEXT | 可空，可选标题 |
| body | TEXT | 不可空，允许空字符串 |
| diary_date | TEXT | 不可空，有效的日历日期 |

数据库建立部分唯一索引：只对 deleted_at 为空的记录限制 diary_date 唯一。它保证一个日期最多存在一篇未删除日记，同时允许回收站中有多篇同日期记录。

页面提前检查日期冲突，用于及时提醒；数据库唯一约束作为最终保护。新建、修改日期和恢复都必须处理约束冲突，返回可识别的业务结果，不以覆盖写入解决冲突。

日记 ID 始终使用 UUID，不用日期作为主键。更改日期不更改 ID。不得用会删除旧行的替换插入方式处理重复日期。

### 4.4 任务表 tasks

包含公共字段，并增加：

| 字段 | SQLite 类型 | 规则 |
| --- | --- | --- |
| title | TEXT | 不可空，去除首尾空白后不能为空 |
| notes | TEXT | 可空，纯文本备注 |
| task_type | TEXT | 仅 DAY、MONTH、YEAR、CUSTOM |
| period_start | TEXT | 不可空，包含在范围内的开始日期 |
| period_end_exclusive | TEXT | 不可空，不包含在范围内的结束边界 |
| is_completed | INTEGER | 不可空，只允许 0 或 1，新任务默认为 0 |
| completed_at | INTEGER | 可空；未完成时为空，完成时非空 |

数据库约束基础合法值及完成状态与完成时间的一致性。自然周期对齐、有效日历日期等业务规则由仓库和日期范围函数验证，避免只靠字符串格式判断。

任务允许标题、日期范围相同但 UUID 不同的多条记录，不对任务日期添加日记式唯一约束。

### 4.5 范围规则

所有范围使用“包含开始、不包含结束”的统一表示。

| 类型和例子 | period_start | period_end_exclusive | 页面显示范围 |
| --- | --- | --- | --- |
| DAY：2026-10-07 | 2026-10-07 | 2026-10-08 | 2026-10-07 |
| MONTH：2026 年 10 月 | 2026-10-01 | 2026-11-01 | 2026 年 10 月 |
| YEAR：2026 年 | 2026-01-01 | 2027-01-01 | 2026 年 |
| CUSTOM：10 月 7 日起 5 天 | 2026-10-07 | 2026-10-12 | 10 月 7 日至 10 月 11 日，共 5 天 |

- DAY 的开始为所选日，结束为下一日。
- MONTH 从月初到下月月初，YEAR 从年初到次年年初。
- CUSTOM 从所选开始日期到第 N 个日历日之后的边界，N 为正整数，且计算结果必须是支持的有效日期。
- 持续天数从起止日期推导，不额外保存一个可能与范围不一致的字段。
- 日期运算按日历进行，不用“当地时间增加 N 个 24 小时”推算自然日期，以免夏令时等因素干扰。
- 30 天与自然月保留不同语义，不自动互相转换任务类型。

### 4.6 索引与列表查询

- 日记：未删除记录的日期唯一索引同时服务于按日期查找和列表排序；回收站按 deleted_at 查询和倒序排序。
- 任务：初始围绕 task_type、period_start 和正常记录条件设计少量复合索引，具体顺序结合实际查询验证。
- DAY、MONTH、YEAR 列表按类型及选定周期匹配，不做跨类型范围重叠汇总。
- CUSTOM 列表单独查询该类型的未删除记录；完成状态筛选对四类任务均可用。
- 普通查询默认排除软删除记录，回收站查询显式只读已删除日记，避免遗漏过滤。
- 不预先建立所有可能的索引，也不为 v0.1 增加同步日志表。

## 5. 关键数据流

以下描述包含已实现与后续目标流程：基础查询、仓库保存／删除／恢复、日记编辑快照、自动保存和离页提交已实现；已保存日记日期修改、编辑页删除、回收站操作及剪贴板界面仍待后续阶段。

### 5.1 日记读取与自动保存

1. 页面状态通过 DiaryRepository 按 UUID 或日期加载日记；仓库返回数据对象或不存在结果。
2. 首次打开空编辑页只建立内存状态，不立即创建数据库行。
3. 输入改变内存中的编辑版本，页面立即响应；状态层安排停顿保存和持续输入期间的周期提交。
4. 保存捕获当前日记 ID、内容快照和编辑版本，经仓库校验后写入 SQLite。
5. 同一日记的保存按顺序执行，允许合并尚未开始的中间快照，但不能丢掉最新版本。
6. 数据库成功后，只标记该快照对应版本已保存；若当前已有更新，继续显示待保存并安排下一次提交。
7. 失败保留当前输入和待保存状态，向页面返回明确错误，允许重试。

编辑版本号是页面内存中的保存协调信息，不是跨设备同步版本。定时器与编辑页生命周期绑定，切换记录时不能让旧定时器写入新记录 ID。释放页面前处理必要保存，不能仅在对象销毁回调中启动一个无人等待的异步保存。

正常导航走可等待的提交路径。进入后台或关闭通知是补充机会，不保证系统一定给出回调或足够执行时间。最终“已保存”必须以数据库提交成功为依据。

### 5.2 日记日期修改、删除和恢复

- 日期修改：先验证目标日期，数据库写入时再依靠唯一约束兜底。冲突不改变原记录日期，不覆盖另一篇日记，编辑内容留在页面。
- 删除：协调同一日记的保存队列，保留当前内容并写入 deleted_at 和 updated_at；相关写入应保持原子性。成功后停止后续自动保存并刷新正常列表及回收站。
- 普通保存不能更新已软删除记录，不能在更新失败后通过无条件插入把记录复活。
- 恢复：将目标记录的 deleted_at 清空并更新 updated_at，保留 ID 和原数据。数据库唯一约束保证冲突时整个恢复失败，记录仍在回收站。
- 恢复前的冲突检查只用于友好提示，不能替代写入时的约束。
- 复制正文：只读已删除内容，由页面调用剪贴板 API；不产生数据库修改，不改变 updated_at。
- 冲突后打开现有日记：查找同日期未删除日记的 UUID，再正常导航，不自动追加或覆盖内容。

### 5.3 任务编辑与完成

1. 页面状态保存尚未提交的表单；切换类型后根据输入计算对应合法范围。
2. 点击保存后，TaskRepository 验证标题、类型和范围，创建或更新同一个任务 ID。
3. 数据库提交成功后返回结果，列表重新查询或接收明确的状态通知，展示持久化后的数据。
4. 标记完成在同一次原子写入中修改 is_completed、completed_at 和 updated_at。
5. 撤销完成同样原子更新状态并清空 completed_at；软删除保留完成状态和完成时间。

本版本优先采用提交成功后刷新列表的简单方式，不要求引入响应式数据库流或乐观更新回滚框架。

### 5.4 错误边界

- 日期冲突、标题无效、范围无效、记录不存在或已删除，属于页面可以理解的业务结果。
- 数据库打开或写入失败向上返回可展示的失败状态，不吞掉错误并伪装成功。
- 操作失败不应清空编辑内容；重试不得重复创建同一条记录。
- 日志不默认打印日记正文或任务备注。调试信息围绕操作类型、记录 ID 和错误原因组织。

## 6. 平台初始化、存储位置和升级

- 应用启动时选择数据库驱动并初始化一个受控的数据库访问入口，上层页面不判断 Android 或 Windows。
- 数据库存放在平台提供的持久化应用数据目录，不放入临时目录、源码目录或 Windows 程序安装目录。
- 使用 path_provider 获取合适目录，path 拼接文件路径，不硬编码盘符或路径分隔符。
- v0.1 无网络数据源，数据读写不依赖登录或联网。
- 从初始版本起管理数据库 schema 版本。升级采用显式迁移，并验证旧记录、UUID 和日期规则保持正确。
- 升级不能以删除并重建用户数据库代替迁移；迁移失败应保留原数据并报告错误。
- 两个业务表之间当前没有需要外键关联的关系，不添加无用途的关联表。

## 7. 为未来演进保留的边界

| 方向 | 当前保留的基础 | 后续才设计和实现的部分 |
| --- | --- | --- |
| 多设备同步 | UUID、统一时刻格式、updated_at、deleted_at、仓库入口 | 服务端版本、同步游标、可靠变更追踪、冲突处理、账号与协议 |
| 图片和附件 | 稳定日记 UUID、数据库升级机制 | 通过日记 UUID 关联的附件模型、文件存储和生命周期 |
| 富文本 | 纯文本正文和升级机制 | 内容格式标识、编辑器、旧文本迁移 |
| 重复任务 | 稳定任务 UUID、日期范围语义 | 重复规则和每次执行实例，不能把单一完成状态当作每日完成历史 |

不在 v0.1 添加无实际协议支撑的 is_synced 标志、服务端字段或设备 ID 字段，也不实现同步器。未来同步可能需要单独的元数据或变更表，不能认为已有时间戳足够处理并发。

每天一篇在本地由唯一约束保证。未来两台设备可能分别创建同一天、不同 UUID 的日记，届时必须明确保留双方内容的冲突策略，不能简单按本机修改时间覆盖，也不能通过去掉约束悄悄改变产品规则。

## 9. 当前实现状态（2026-10-09）

- `app/app_dependencies.dart` 是组装入口：平台驱动 → 应用数据目录中的 dairy.sqlite → AppDatabase → 两个仓库。
- `app/dairy_app.dart` 提供中文 Material 本地化、初始化等待和失败重试；`app_shell.dart` 在窗口宽度 720 处切换导航布局。
- `models/local_date.dart` 以日历日期表达业务日期，`task_period.dart` 验证自然周期与 CUSTOM，避免使用本地午夜加固定小时数。
- `data/database/schema.dart` 管理 schema v1，两张表和三个索引；尚无历史版本迁移，未知升级和降级明确失败，不能删除用户数据库。
- `*_queries.dart` 包含 SQL 和行映射；仓库提供查询、幂等内容保存、软删除、日记恢复及任务状态操作。
- 新草稿通过仓库 `newId()` 取得 ID，保存和失败重试复用；仅取得 ID 不插入记录。普通保存保留创建时间和任务完成元数据，禁止复活软删除记录。
- 日记列表接入“写今天”、选择日期新建和已有记录编辑；当天已有日记时复用原记录，显式新建遇到重复日期时弹窗提醒。
- `diary_editor_page.dart` 使用 Material 输入框、Navigator、PopScope 和生命周期观察；返回前等待保存，失败保留页面与输入，日期冲突提示不覆盖已有日记。
- `diary_editor_model.dart` 使用 ChangeNotifier 与 Dart Timer：约 800 毫秒停顿提交、约 5 秒持续输入提交。一个写入执行期间合并待保存输入，后续提交最新快照；按内存编辑版本判断是否全部保存，失败暂停并允许重试。
- 编辑状态通过构造函数接收 `DiarySave` 回调，生产环境传入现有仓库的 `save`；测试可控制写入延迟和失败，不增加仓库框架或新依赖。首次输入前不创建记录，保存后清空不删除。
- 新建草稿首次持久化前可以选择日期；已保存日记本阶段固定日期，编辑内容保留创建时间。产品中的显式日期修改另行实现。
- 数据库 schema 保持 v1，自动保存直接写入既有日记表，不添加独立草稿表、同步版本或历史表。
- 回收站与任务页面仍为只读列表，删除／恢复／复制及任务编辑等操作按后续阶段实现。
- ChangeNotifier 列表状态处理加载、失败重试与过期请求结果，UI 不直接引用数据库。
- Android 和 Windows 已生成平台工程。iOS 仅作为未来候选，在驱动初始化处兼容，不视为当前已适配平台。
- 自动化检查与平台构建的具体结果见 README.md；平台工具链缺失不能算作发行验收通过。
