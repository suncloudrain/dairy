## 1. 总体结构

采用轻量分层，按功能组织页面。不引入完整的复杂架构框架，也不为每个操作预先增加额外层。

```text
页面：日记、回收站、任务
        ↓ 用户操作       ↑ 状态与结果
页面状态：编辑内容、加载、筛选、保存调度
        ↓ 业务操作       ↑ 数据对象与错误
数据仓库：日记规则、任务规则、统一的数据访问入口
        ↓ 存储请求       ↑ 查询和提交结果
SQLite 数据层：数据库连接、查询、事务、约束、版本升级
```

依赖从上向下。数据层不引用页面；页面不执行 SQL；仓库不访问输入框或导航组件。日期范围计算和数据对象使用普通 Dart 表达，不依赖 Widget。

| 职责 | 内容 | 边界 |
| --- | --- | --- |
| 页面层 UI | 显示内容、接收输入、弹窗、导航、调用剪贴板 | 不决定数据库表结构，不直接写 SQL |
| 页面状态层 | 当前输入、筛选、加载状态、自动保存定时器、保存序列、失败重试 | 不决定数据库文件路径，不把导航当作数据持久化 |
| 数据仓库层 Repository | 日记与任务读写入口、规则校验、UUID 和时间赋值、软删除和恢复 | 不依赖 Flutter 页面；把日期冲突等结果返回调用方 |
| SQLite 数据层 | 打开数据库、参数化查询、事务、索引和约束、升级 | 不决定按钮文案或页面布局 |

“仓库”是操作数据的统一入口，不是另一份数据库。“事务”使相关修改一起成功或一起失败。例如完成状态和完成时间不能只保存一个。

## 4. 数据模型

### 4.1 存储约定

- SQLite 字段采用 snake_case；Dart 属性采用相应的 camelCase。
- UUID 存为 TEXT 主键并显式要求非空；创建后保持不变。
- 日历日期存为固定宽度的 `YYYY-MM-DD` 文本，必须是有效日期。
- 创建、修改、完成、删除时刻存为 UTC Unix 毫秒整数，显示时转换到本地时区。
- 可空字段使用 NULL 表示没有值；布尔状态存为整数 0 或 1。
- 日记正文允许空字符串，以支持编辑和清空后保留记录。
- 只有实际数据变化才更新 updated_at，浏览或重复保存相同内容不更新时间。
- 时间来自本机时钟，不假设跨设备时间严格有序，不把 updated_at 当作同步版本号。
- 读取时构造数据对象，写入前完成业务校验；SQL 参数使用参数绑定。

日期与时刻的含义不同：2026-10-05 的日记可以在 2026-10-07 创建。日记日期和任务范围不因切换时区而转换到前一天或后一天；“今天”根据设备当前本地日历计算。

### 4.2 公共字段

下列字段同时存在于日记和任务表，不需要额外的公共实体表。

| 字段 | SQLite 类型 | 规则 |
| --- | --- | --- |
| id | TEXT | 主键、不可空、UUID v4 |
| created_at | INTEGER | 不可空，首次创建时写入，后续保留 |
| updated_at | INTEGER | 不可空，实际修改、删除或恢复时更新 |
| deleted_at | INTEGER | 可空；NULL 为正常记录，非空为软删除记录 |

### 4.3 日记表 diary_entries

包含公共字段，并增加：

| 字段 | SQLite 类型 | 规则 |
| --- | --- | --- |
| title | TEXT | 可空，可选标题 |
| body | TEXT | 不可空，允许空字符串 |
| diary_date | TEXT | 不可空，有效的日历日期 |

数据库建立部分唯一索引：只对 deleted_at 为空的记录限制 diary_date 唯一。它保证一个日期最多存在一篇未删除日记，同时允许回收站中有多篇同日期记录。

页面提前检查日期冲突，用于及时提醒；数据库唯一约束作为最终保护。新建、修改日期和恢复都必须处理约束冲突，返回可识别的业务结果，不以覆盖写入解决冲突。

日记 ID 始终使用 UUID，不用日期作为主键。更改日期不更改 ID。不得用会删除旧行的替换插入方式处理重复日期。

### 4.4 任务表 tasks

包含公共字段，并增加：

| 字段 | SQLite 类型 | 规则 |
| --- | --- | --- |
| title | TEXT | 不可空，去除首尾空白后不能为空 |
| notes | TEXT | 可空，纯文本备注 |
| task_type | TEXT | 仅 DAY、MONTH、YEAR、CUSTOM |
| period_start | TEXT | 不可空，包含在范围内的开始日期 |
| period_end_exclusive | TEXT | 不可空，不包含在范围内的结束边界 |
| is_completed | INTEGER | 不可空，只允许 0 或 1，新任务默认为 0 |
| completed_at | INTEGER | 可空；未完成时为空，完成时非空 |

数据库约束基础合法值及完成状态与完成时间的一致性。自然周期对齐、有效日历日期等业务规则由仓库和日期范围函数验证，避免只靠字符串格式判断。

任务允许标题、日期范围相同但 UUID 不同的多条记录，不对任务日期添加日记式唯一约束。

### 4.5 范围规则

所有范围使用“包含开始、不包含结束”的统一表示。

| 类型和例子 | period_start | period_end_exclusive | 页面显示范围 |
| --- | --- | --- | --- |
| DAY：2026-10-07 | 2026-10-07 | 2026-10-08 | 2026-10-07 |
| MONTH：2026 年 10 月 | 2026-10-01 | 2026-11-01 | 2026 年 10 月 |
| YEAR：2026 年 | 2026-01-01 | 2027-01-01 | 2026 年 |
| CUSTOM：10 月 7 日起 5 天 | 2026-10-07 | 2026-10-12 | 10 月 7 日至 10 月 11 日，共 5 天 |

- DAY 的开始为所选日，结束为下一日。
- MONTH 从月初到下月月初，YEAR 从年初到次年年初。
- CUSTOM 从所选开始日期到第 N 个日历日之后的边界，N 为正整数，且计算结果必须是支持的有效日期。
- 持续天数从起止日期推导，不额外保存一个可能与范围不一致的字段。
- 日期运算按日历进行，不用“当地时间增加 N 个 24 小时”推算自然日期，以免夏令时等因素干扰。
- 30 天与自然月保留不同语义，不自动互相转换任务类型。

### 4.6 索引与列表查询

- 日记：未删除记录的日期唯一索引同时服务于按日期查找和列表排序；回收站按 deleted_at 查询和倒序排序。
- 任务：初始围绕 task_type、period_start 和正常记录条件设计少量复合索引，具体顺序结合实际查询验证。
- DAY、MONTH、YEAR 列表按类型及选定周期匹配，不做跨类型范围重叠汇总。
- CUSTOM 列表单独查询该类型的未删除记录；完成状态筛选对四类任务均可用。
- 普通查询默认排除软删除记录，回收站查询显式只读已删除日记，避免遗漏过滤。
- 不预先建立所有可能的索引，也不为 v0.1 增加同步日志表。

## 5. 关键数据流

以下核心业务流程均已有实现：查询、保存、软删除、恢复、日记自动保存与离页提交、显式改期、回收站详情及手动复制。设备上的完整交互验收与发行验证仍须独立执行。

### 5.1 日记读取与自动保存

1. 页面状态通过 DiaryRepository 按 UUID 或日期加载日记；仓库返回数据对象或不存在结果。
2. 首次打开空编辑页只建立内存状态，不立即创建数据库行。
3. 输入改变内存中的编辑版本，页面立即响应；状态层安排停顿保存和持续输入期间的周期提交。
4. 保存捕获当前日记 ID、内容快照和编辑版本，经仓库校验后写入 SQLite。
5. 同一日记的保存按顺序执行，允许合并尚未开始的中间快照，但不能丢掉最新版本。
6. 数据库成功后，只标记该快照对应版本已保存；若当前已有更新，继续显示待保存并安排下一次提交。
7. 失败保留当前输入和待保存状态，向页面返回明确错误，允许重试。

编辑版本号是页面内存中的保存协调信息，不是跨设备同步版本。定时器与编辑页生命周期绑定，切换记录时不能让旧定时器写入新记录 ID。释放页面前处理必要保存，不能仅在对象销毁回调中启动一个无人等待的异步保存。

编辑页右上角“保存并返回”、左上角返回和系统返回复用同一提交路径：冻结输入 → DiaryEditorModel.flush → 等待最新快照持久化 → Navigator 返回 → 列表重新读取。失败留在页面并恢复输入；空白未输入草稿不会因此创建记录。进入后台或关闭通知是补充机会，不保证系统一定给出回调或足够执行时间。最终“已保存”必须以数据库提交成功为依据。

### 5.2 日记日期修改、删除和恢复

- 日期修改：`DiaryEditorPage._chooseDate` 收到日历确认后调用 `_changeDate` → `DiaryEditorModel.changeDate` 标记独占改期 → `_flushContent` 等待已有快照并保存原日期下的最新内容 → 既有 `DiaryRepository.save`／`DiaryQueries.updateContent` 在事务中提交新日期 → 成功后才更新 `_date` 和 `_entry`。两个保存步骤有明确先后；原内容提交成功后，改期仍可能独立失败。
- 改期期间输入和离页暂时禁用；公开 `flush` 返回正在进行的改期 Future，后台通知不会另起一次旧日期写入。日期冲突和其他失败保持原日期，`failedDate` 仅在内存保留重试目标，页面显示“重试修改日期”；正文预提交失败则走已有“重试保存”。
- 改期成功只更新页面和提示，不调用 Navigator 返回；继续输入沿用新日期。用户“保存并返回”或正常返回后列表重新读取并按新日期排序。新草稿仍使用 `chooseDate`，只选日期不创建记录。
- 删除：`DiaryEditorPage._delete` 确认后调用 `DiaryEditorModel.deleteEntry`；`_flushContent` 等待旧快照并提交最新内容，再调用注入的 `DiaryRepository.softDelete` → `DiaryQueries.setDeleted`，在同一事务中写 deleted_at 和 updated_at。成功后 `_deleted` 将本编辑会话置为不可再写入，取消计时器，页面返回，正常列表重新查询。
- 内容提交与软删除是先后两次操作，不是跨步骤事务；内容成功但删除失败时，最新内容仍保存在正常记录中，显示“重试删除”。内容保存失败则不尝试删除。公开 `flush` 在删除进行中返回同一个 Future，不会另起旧快照写入；删除与改期互斥。
- 普通保存不能更新已软删除记录，不能在更新失败后通过无条件插入把记录复活。
- 恢复：`DiaryTrashDetailPage._restore` → `DiaryTrashDetailModel.restore` → `DiaryRepository.restore` → `DiaryQueries.setDeleted` 清空 deleted_at 并更新 updated_at，保留 ID 和原数据。数据库唯一约束保证冲突时整个恢复失败；详情页展示错误，不离页、不覆盖。成功返回回收站，`DiaryPage._openDeleted` 重新加载；退出回收站后正常列表也重新读取。
- 恢复前的冲突检查只用于友好提示，不能替代写入时的约束。
- 复制正文：详情页使用 SelectableText 展示正文，用户点击“复制正文”后由页面调用 Flutter Clipboard.setData，成功或失败都有提示；不产生数据库修改，不改变 updated_at。状态对象不接触剪贴板或 Navigator。
- 冲突后打开现有日记：`DiaryTrashDetailModel.findExisting` 通过仓库查找同日期未删除记录，页面再进入原有 DiaryEditorPage；返回仍在回收站详情。打开本身不追加、覆盖或恢复任何内容，用户可以自行粘贴编辑。

### 5.3 任务编辑与完成

1. `TaskEditorPage` 的输入框／类型选择把变化交给 `TaskEditorModel`；表单和初始快照留在内存，`dirty` 用于离页提示。草稿会话 UUID 固定，输入不写库。
2. 点击“保存”调用 `TaskEditorModel.saveTask`：校验必填标题和有效范围、进入忙碌状态，再调用注入的 `TaskRepository.save`。
3. 仓库复用现有事务与 `TaskQueries` 写入 SQLite。编辑保留 ID、created_at 和完成状态；失败保留表单，不离页，重试复用同一 ID。
4. 成功后 `Navigator.pop` 返回持久化任务，`TasksPage._openTask` 调用 `TaskListModel.focusTask`，选择其类型／周期并把完成筛选重置为“全部”，然后 `load` 重新读取。
5. 列表复选框 → `TaskListModel.setCompleted` → `TaskRepository.setCompleted` → SQLite 原子更新完成状态、completed_at 和 updated_at → 查询刷新。撤销清空完成时间。
6. 删除弹窗确认后，列表或编辑状态调用 `TaskRepository.softDelete`；只写删除标记和修改时刻，保留完成信息。编辑页有未保存输入时提醒将其放弃；成功才返回／刷新。
7. `task_period_controls.dart` 仅提供显示和日期选择；自然周期与自定义范围计算仍由 `TaskPeriod` 承担。月／年选择不借助无关的“某一天”表达。

页面处理导航、弹窗和输入控制器；状态对象处理表单、请求和错误，不依赖 Navigator；仓库不引用 Widget，页面不执行 SQL。使用既有 schema v1，没有新增依赖、草稿表或同步服务。

本版本优先采用提交成功后刷新列表的简单方式，不要求引入响应式数据库流或乐观更新回滚框架。

### 5.4 错误边界

- 日期冲突、标题无效、范围无效、记录不存在或已删除，属于页面可以理解的业务结果。
- 数据库打开或写入失败向上返回可展示的失败状态，不吞掉错误并伪装成功。
- 操作失败不应清空编辑内容；重试不得重复创建同一条记录。
- 日志不默认打印日记正文或任务备注。调试信息围绕操作类型、记录 ID 和错误原因组织。

## 6. 平台初始化、存储位置和升级

- 应用启动时选择数据库驱动并初始化一个受控的数据库访问入口，上层页面不判断 Android 或 Windows。
- 数据库存放在平台提供的持久化应用数据目录，不放入临时目录、源码目录或 Windows 程序安装目录。
- 使用 path_provider 获取合适目录，path 拼接文件路径，不硬编码盘符或路径分隔符。
- v0.1 无网络数据源，数据读写不依赖登录或联网。
- 从初始版本起管理数据库 schema 版本。升级采用显式迁移，并验证旧记录、UUID 和日期规则保持正确。
- 升级不能以删除并重建用户数据库代替迁移；迁移失败应保留原数据并报告错误。
- 两个业务表之间当前没有需要外键关联的关系，不添加无用途的关联表。

## 7. 为未来演进保留的边界

| 方向 | 当前保留的基础 | 后续才设计和实现的部分 |
| --- | --- | --- |
| 多设备同步 | UUID、统一时刻格式、updated_at、deleted_at、仓库入口 | 服务端版本、同步游标、可靠变更追踪、冲突处理、账号与协议 |
| 图片和附件 | 稳定日记 UUID、数据库升级机制 | 通过日记 UUID 关联的附件模型、文件存储和生命周期 |
| 富文本 | 纯文本正文和升级机制 | 内容格式标识、编辑器、旧文本迁移 |
| 重复任务 | 稳定任务 UUID、日期范围语义 | 重复规则和每次执行实例，不能把单一完成状态当作每日完成历史 |

不在 v0.1 添加无实际协议支撑的 is_synced 标志、服务端字段或设备 ID 字段，也不实现同步器。未来同步可能需要单独的元数据或变更表，不能认为已有时间戳足够处理并发。

每天一篇在本地由唯一约束保证。未来两台设备可能分别创建同一天、不同 UUID 的日记，届时必须明确保留双方内容的冲突策略，不能简单按本机修改时间覆盖，也不能通过去掉约束悄悄改变产品规则。

## 9. 当前技术组成与实现边界（2026-10-17）

本节是当前代码的技术快照，代码演进后随之更新；它不按日期追加迭代流水。用户可见功能概况见 [README.md](../README.md)，历史变化与当次验证见 [CHANGELOG.md](../CHANGELOG.md)。前面的设计流程包含已实现与待实现部分，以本节区分。

| 部分 | 当前实际组成与职责 | 当前边界 |
| --- | --- | --- |
| 应用组装与导航 | `app_dependencies.dart` 选择平台驱动、应用数据目录和仓库；`dairy_app.dart` 处理中文本地化、启动及重试；`app_shell.dart` 在窗口宽度 720 处切换导航 | Android／Windows 工程已建立；iOS 仅有驱动兼容分支，尚未适配或验证 |
| 模型 | `LocalDate` 表达独立日历日期；`TaskPeriod` 验证自然周期与 CUSTOM；日记／任务使用不可变对象 | 日期与 UTC 时刻分开；没有同步版本、富文本或附件模型 |
| 页面与列表状态 | 日记列表与编辑器、回收站列表和只读详情、任务列表；ChangeNotifier 处理加载、操作、筛选、刷新与过期请求结果 | 完整平台交互验收待完成；没有全局响应式数据库缓存 |
| 日记编辑状态 | `DiaryEditorModel` 使用定时器、固定 UUID 和串行快照；`changeDate`／`deleteEntry` 互斥，删除前等待保存、成功后停止会话写入；注入仓库 save／softDelete 回调 | 没有持久化草稿；失败目标只在内存；内存版本不是同步版本 |
| 日记页面协调 | `DiaryEditorPage` 管理改期、删除确认、输入冻结、Navigator、PopScope 与生命周期通知；正常返回等待 flush；`DiaryPage` 管理列表和回收站导航及重读 | 改期成功留在编辑页，删除成功返回列表；没有永久删除或批量操作 |
| 回收站详情 | `DiaryTrashDetailPage` 展示只读内容、调用 Clipboard、处理导航；`DiaryTrashDetailModel` 调用仓库恢复／查找现有日记，管理错误和忙碌状态 | 恢复失败不离页；不自动复制、合并或覆盖；无任务回收站 |
| 任务编辑 | `TaskEditorPage` 管理表单控制器、PopScope、关闭通知与确认；`TaskEditorModel` 管理内存草稿、校验、忙碌与保存／删除；`task_period_controls.dart` 复用日期选择与显示 | 手动保存；无持久化草稿、任务回收站或完成历史；完整平台交互验收待完成 |
| 仓库 | 日记／任务仓库统一业务校验、事务、UUID、时间及保存／查询／软删除／恢复／完成入口 | 数据入口不等于对应 UI 已交付；普通保存不复活删除记录，相同内容不更新时间 |
| SQLite | schema v1，两张表、三个索引；`AppDatabase` 管理连接，`*_queries.dart` 处理 SQL 与行映射 | 没有真实历史迁移；未知升／降级明确失败，不删除用户数据。未来升版必须增加实际迁移 |

依赖边界继续保持“页面 → 页面状态 → 仓库 → SQLite”，页面不执行 SQL，仓库不引用 Widget。日记自动保存直接写入既有日记表，不添加另一套保存流程或草稿表；实际流程详见第 5 节。

验证状态分开维护：本文件说明技术组成与限制，README 给出最近摘要，CHANGELOG 保存各次检查结果。工具链可用、构建通过与设备／发行验收是不同状态，不能互相替代。
